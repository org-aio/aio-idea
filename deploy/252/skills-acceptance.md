# 配对设备 Skill 双向同步验收

2026-09-16，在正式入口 https://aio.addzero.site，使用既有 zjarlin 账号和已配对的 `addzeroMacBook-Pro.local` 验证。未创建新账号或保存账号密码。

## 设计与边界

- 配对、设备凭据、租户身份、撤权及能力检查属于 AIO 宿主公共基础设施；本次没有新增一个需要独立安装的配对插件。智能体通过宿主的 worker 服务通道使用设备能力。
- Skill 数据及管理接口属于 Agent 插件，使用插件专属 PostgreSQL 存储，按租户和用户隔离，正文及历史版本加密保存。没有在宿主增加一套 Skill 业务表。
- 设备主动连接 AIO。`skills.sync` 同时需要宿主允许、已启用的插件声明和设备主动开启。浏览器不能伪造设备调用上下文。
- 本机授权目录为 `/Users/zjarlin/.agents/skills`，每 30 秒同步。同步正文、脚本和资源，排除隐藏目录、Git、缓存及已知凭据文件，拒绝链接和越界路径。同步或读取脚本不会自动执行脚本。
- 同一路径使用本地、云端、已同步基线三方比较；双方都修改时保留冲突，由用户明确选版本。写入使用版本比较，删除传播墓碑，本机覆盖/删除前保存旧文件，云端保留加密历史。
- Agent 增加 `skill_list`、`skill_read` 按需读取技能。通用 shell、鼠标键盘及任意文件系统访问不在本次新增能力内。

参考 [DeepSeek Harness](https://www.deepseek.com/harness/) 的插件组合、工具与技能分离，以及 [ByteDance UI-TARS Desktop](https://github.com/bytedance/UI-TARS-desktop) 的客户端执行方式。这里不声称验证了闭源豆包客户端的内部实现。

## 正式环境实测

1. Chrome 工作空间已显示“智能体”父菜单，其下包含“对话”“记忆图谱”“Skill 管理”。Skill 页面能新建、编辑和确认删除文件，并显示设备同步时间。
2. 首轮从本机同步 **35 个 Skill、132 个文件、4,167,386 字节**。同步前目录备份为 `/tmp/aio-skills-before-20260916.tgz`；基线清单为 `/tmp/aio-skills-before-manifest.json`。原始 132 个文件的本机与云端哈希逐一相同。
3. 在真实网页新建 `aio-sync-acceptance/SKILL.md`，内容包含 `web-to-local-20260916`；后台 worker 自动下载，本机读取确认内容相同。
4. 只在该临时文件追加 `local-to-web-20260916`，等待自动同步后打开网页管理弹窗，正文同时显示两个标记。
5. 在网页确认删除该临时文件，后台自动删除本机文件，验证私有同步状态目录中的备份仍包含两个标记。随后移除已空的临时目录。其他文件未因验收而删除。
6. 同期其他操作新增的 Skill 被后台自动纳入。验收结束快照为 36 个 Skill、134 个活动文件；原始清单哈希全部匹配，无冲突。临时验收文件只留下云端墓碑和本机恢复备份。
7. macOS 的 `bootout` 后立即 `bootstrap` 曾出现短暂错误 5，已修复有界重试；连续两次真实 `skills-enable` 成功，LaunchAgent 处于 `running`。Linux 配置更新改为明确重启服务，但本次没有进行 Linux 实机验证。
