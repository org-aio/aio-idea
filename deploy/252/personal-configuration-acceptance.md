# 多设备个人配置验收（2026-09-16）

## 实际交付

AIO 账号菜单新增“个人配置”：配置文件、环境变量、应用命令、个人资源、同步设备。每台设备独立配对，沿用 AIO 账号；一次授权后持续出站连接、自动重连，不保存账号密码。个人配置属于宿主独立领域，日常同步不依赖智能体或模型调用。

配置正文和历史加密保存，以租户＋用户隔离。共享、操作系统、单设备覆盖按优先级生效。文件变化使用三方合并；JSONC 按键合并并保留注释，无法自动合并时保留双方版本并在网页选择。云端 CAS、客户端文件 CAS、加密基线和写前备份共同避免覆盖并发修改。

环境变量以本机 `environment.json` 和网页双向管理，生成按字面值引用的 shell 脚本；当前已运行进程的环境无法由 worker 外部修改，新终端或手动 source 后生效。已有 shell export/alias 随导入的配置文件同步，不执行脚本提取变量。应用启动命令目前支持 macOS bundle ID，需要对应应用已经安装。

安装包和杂物复用 restic 归档，提供个人资源目录和选择设备恢复。保留原件，不自动执行安装程序；恢复目标须不存在，保留原始路径层级。

真实 252 Docker 网络验证由 `tests/protocol/personal-network.mjs` 执行：

1. 两台独立设备位于 NAT 后，无端口映射，禁止新入站，仅允许 DNS 与 HTTPS 出站，正常接收同一账号配置。
2. 防火墙阻断设备 B 的 HTTPS；B 本机与在线端分别修改不同键；解除阻断后自动合并并回传设备 A，无重复配对。
3. 更换设备 B 的 NAT 子网地址后继续双向同步。
4. 网页撤销 B 后 worker 退出，A 的配对不受影响。

测试容器、网络和独立数据库测试 schema 已清理，临时 PostgreSQL 已停止。代理 403 的恢复另由 CLI 自动测试验证；网络完全阻断时不能实时同步，恢复出站 HTTPS 后重新对账。

## 新设备接入

安装 AIO 个人资源中的 0.6.0 tar 包后：

```sh
npm install --global ./aio-space-0.6.0.tgz
aio-space connect
aio-space config-enable
```

浏览器登录同一租户下的同一账号授权。首次已有同名配置内容不同会报告冲突，可在“同步设备”选择本机或云端。需要纳管第二设备自己独有的文件时，再运行 `config-import --preview` 和 `config-import`。具体命令、作用域、容量、备份与失败处理见空间管家 README 及宿主 personal_config README。
