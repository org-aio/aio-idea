# Worker 长期通道验收

2026-09-16，正式入口 https://aio.addzero.site。

原实现是一次授权、长期设备凭据和每 5 秒短轮询。本次改为一次授权后的出站 HTTPS 长轮询，每次等待最多 25 秒，收到任务立即续接；15 秒独立心跳、20 秒任务续约、1～30 秒带抖动的重连退避。配对码仍为十分钟的一次性授权入口，已配对设备不随它过期。

## 真实 NAT 和防火墙

测试脚本：`tests/protocol/worker-network.mjs`。在 252 新建独立 Docker bridge 和容器，经公网域名、Cloudflare 和正式 AIO 服务通信；没有发布客户端端口。只在新容器网络命名空间修改 iptables，宿主及真实 Mac 防火墙未改动。

| 场景 | 结果 |
| --- | --- |
| Docker NAT，禁止全部新入站，仅 DNS/443 出站 | 任务完成；入站监听探针连接失败，INPUT DROP 计数为 2 |
| 出站 TCP reset 后放行 | 3.5 秒内完成恢复后的任务 |
| 完全阻断 HTTPS 出站 | 正确显示离线；DROP 计数 65，85.9 秒后观察到离线（心跳阈值为距最后接触 90 秒） |
| 解除 HTTPS 出站阻断 | 无重新配对，31.0 秒完成任务 |
| 私网 IP 从 172.20.0.2 换为 172.22.0.2 | 无重启或重新配对，37.4 秒完成任务 |
| 直连 HTTPS 仍被拒绝，仅允许独立 HTTP CONNECT 代理 | 7.1 秒完成任务，TLS 校验保留 |
| 网页账号撤销测试设备 | worker 实际退出，日志确认撤权 |

以上耗时含管理 API、排队和结果查询，不作为所有网络的延迟保证。长期禁止全部出站时无法通信；设计目标是明确离线、保护未知任务结果、网络放行后自恢复。这里验证的是 Docker NAT 和实际公网路径，没有把它扩张为所有运营商、防火墙或 TLS 检查设备的兼容保证。
